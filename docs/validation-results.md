# 双角色二进制功能验证

本页记录指定 ARM 二进制在 ANTSDR E310 v1 上的短双向加密交互结果，供判断功能覆盖范围。结果只适用于列出的二进制；复现步骤见 [互通运行](interoperability.md)，构建与离线覆盖见 [源码范围与验证状态](source-status.md)。

## 二进制与对端条件

测试使用 G/T 两个节点程序，WS63 对端分别运行预装的官方 SDK 1.10.108 server/client 示例固件，server 支持 WRITE。

通过功能验证的二进制 SHA-256 如下：

```text
sle_gnode 185712c7eeda1ed3530357eef77bdfb6b68750085a8e26782841335cea00798e
sle_tnode aa43f878c54f027bc14f78c125cc1c57273481a13c5f26be84571110ea7bf7b2
```

WS63 固件版本依据部署信息与 UART 角色输出判断，缺少完整读回的全片哈希，因此对端固件身份未通过逐字节校验。

## 功能结果

每个成功会话都在同一连接内发送两条消息，再验证关闭 stdin 后仍能接收，最后用 SIGINT 退出。

| 项目 | E310 G ↔ WS63 server | E310 T ↔ WS63 client |
| --- | --- | --- |
| 协商 MTU | 251 | 520 |
| E310 发给对端 | `OPEN-G-001/002`，均收到加密成功响应 | `OPEN-T-001/002`，对端 UART 均收到 |
| 对端发给 E310 | `SERVER-OPEN-001`、`SERVER-AFTER-EOF` | `CLIENT-OPEN-001`、`CLIENT-AFTER-EOF` |
| 字节检查 | 含 CRLF 的完整拼接字节一致 | 含 CRLF 的完整拼接字节一致，接收 4 个加密 WRITE 片段 |
| stdin EOF | 关闭输入后约 0.4 秒再次从对端发送数据，正常接收 | 同左 |
| MIC 成功 / 失败计数 | 11 / 0 | 21 / 0 |
| SIGINT | 清理退出，退出码 1，设备属性恢复成功 | 同左 |

发送给 WS63 的每条测试行均附加 CRLF。两种模式的就绪提示一致，发送提示标记为“已排队”；是否送达由对端响应或 UART 接收结果确认。

G 的应用输出直接记录了 EOF 和退出信号编号 2。T 的判断依据是测试端关闭 stdin、发送 SIGINT 后，应用继续收包并完成信号退出和属性恢复；T 应用未单独记录处理 EOF 的时刻或具体信号编号。两者的功能观察一致，证据细度不同。

## 适用限制

T 出现过未连接，需要重试：失败时未收到对端帧，未进入加密就绪状态；相同二进制和参数在重试后通过。测试中还观察到 WS63 复位/暂停状态异常，尚未隔离根因；未评估连接成功率，也不能认定相关问题已解决。测试也没有独立确认另一块 WS63 的射频处于静默状态。

结果只覆盖短消息、EOF 和 SIGINT，没有验证全部停止信号、长期稳定性、满 MTU 负载、吞吐、断线重连或标准符合性。该测试也未从头验收 [WS63 对端准备流程](ws63-build.md)。
