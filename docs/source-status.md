# 源码范围与验证状态

本工程提供 ANTSDR E310 v1 的 G/T 两种节点程序，用于与 WS63 官方 SDK 1.10.108 示例进行双向加密通信。本页区分代码实现、离线测试和实机覆盖，便于确定构建与验收范围；运行步骤见 [E310 构建](e310-source.md) 和 [互通运行](interoperability.md)。

## 源码与运行边界

公开源码覆盖 E310 用户态收发链路。WS63 固件和 E310 的底层运行环境需要另行准备。

| 部分 | 提供内容 |
| --- | --- |
| E310 运行程序 | [sle_gnode.c](../sle-rt/sle_gnode.c)、[sle_tnode.c](../sle-rt/sle_tnode.c)，以及物理层、IIO、无线调度、连接、配对、CMTC、SSAP、SDU 模块 |
| 密码学与构建 | [Makefile](../sle-rt/Makefile)、[Mbed TLS 3.6.7 固定子模块](dependencies.md)、[密码学封装](../sle-rt/sle_crypto.c)与[编译配置](../sle-rt/sle_mbedtls_config.h) |
| 离线测试 | [tests/](../tests/) 中的 16 个 C 回归程序、ARM NEON 解调测试和 15 组合成配对预期值校验 |
| WS63 对端 | [官方示例选择与 server WRITE 修改说明](ws63-build.md)；不附带 WS63 源码或构建工具 |
| 硬件支持 | 两份 WS63 OpenOCD 配置；E310 v1 通过 Linux IIO 运行，环境要求见 [硬件说明](hardware.md) |

节点默认使用 standard 资源字布局和 `0x200` 配对参数。G 默认启用配对，T 默认使用 predictive 回复。代码提供校准、发送观察（TX witness）、CMTC 计数、MTU 520 支持、发送分片和队列预留；协商结果及实际单包容量仍受对端与运行参数限制。

兼容参数可显式选择，但参数存在不代表相应旧 SDK 已通过回归。运行程序不提供原始 IQ 诊断采集或密钥转储开关。运行时密钥由系统随机源生成，固定合成材料仅用于测试，见 [密钥生成](key-generation.md)。

## 双角色交互行为

使用 `--interactive 1` 时，两种角色在同一连接中持续处理终端输入与对端数据。

| 行为 | G 节点 | T 节点 |
| --- | --- | --- |
| 本端输入 | 向对端发起加密 WRITE，逐个等待请求响应 | 向对端发送加密通知 |
| 对端数据 | 显示收到的通知 | 显示收到的 WRITE |
| stdin EOF | 继续接收，保留连接 | 同左 |
| 断线后的未发送输入 | 保留供后续连接处理 | 同左 |
| Ctrl-C 等停止信号 | 清理资源后退出；操作者停止不表示业务验收通过 | 同左 |

两种模式都限制输入队列容量。发送提示“已排队”表示本地接收了输入，不表示对端已处理。具体命令、退出码和日志字段见 [互通运行](interoperability.md)。

## 已验证效果

下表区分构建成功、离线断言和空口功能。测试范围与运行命令见 [E310 构建](e310-source.md)，配对测试的具体边界见 [安全实现](security.md)。

| 验证类别 | 已验证效果 | 限制 |
| --- | --- | --- |
| host 构建 | G/T 两个运行程序均可构建 | 不验证板上性能或射频时序 |
| ARM 构建与 QEMU | G/T 两个 ARM 程序构建成功；16 个 C 测试及额外 NEON 解调测试在 QEMU 中通过 | 仿真只验证所测功能，不代表 ARM 板上的实时性 |
| 协议与交互离线验证 | host 的 16 个 C 测试及 15 组合成配对预期值校验通过；G 应用回归 3414 项检查、0 失败；T 覆盖管道输入、背压、MTU/SDU、EOF/信号、加密边界 WRITE 处理及主函数清理路径 | 信号用例在模拟无线启动后注入，没有模拟完整配对就绪后的退出；断言集合不等于完整协议覆盖或安全审计 |
| 双角色实机功能 | 指定 ARM 二进制与 WS63 server/client 完成短双向加密通信，覆盖同连接两条发送、反向完整字节接收、stdin EOF 后继续接收及 SIGINT 清理退出 | T 出现过未连接，需要重试；未评估连接成功率。仅覆盖指定二进制与对端，详见 [功能验证](validation-results.md) |

host / ARM 的严格编译验证使用 `-Wall -Wextra -Werror`。host 合成配对校验使用 Python cryptography 50.0.2。

## 未覆盖能力与使用限制

当前实现和验证仍有以下边界：

- 代码覆盖互通所需的协议子集，不提供完整 SLE 协议栈或正式标准符合性认证；安全能力和限制见 [安全说明](security.md)。
- 实机仅覆盖短消息、EOF 和 SIGINT。其他停止信号、跨连接输入保留及异常边界依赖离线回归，未逐项上板；长期稳定性、满 MTU 负载、吞吐和断线重连未完成实机验收。
- [WS63 文档准备流程](ws63-build.md) 尚未从头完成验收。对端需要完整官方 SDK 和 FBB 工具；厂商预编译协议库不包含在本工程，也没有从源码重建。
- 用户态程序的构建验证不等于 E310 启动固件、内核与 FPGA 的完整源码重建；运行环境见 [硬件说明](hardware.md)。
